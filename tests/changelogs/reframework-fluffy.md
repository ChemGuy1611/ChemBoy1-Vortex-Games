# reframework-fluffy suite Changelog

Covers `template-reframework-fluffy`. Suite file: `tests/templates/reframework-fluffy.test.js`.

## [2026-10-11]

- Changed: the template now has a `HAS_DEMO` guard, a multi-folder loose lua installer, `lastIndexOf` cuts, a case-insensitive nested archive check and `"EACCES"`. The four `known gap` tests that pinned the old behavior (nested `.ZIP`, no demo executable, demo executable named like the game, `EACCESS`) now assert the fixed result and lost their `known gap:` prefix; the loose lua test that pinned "only the first script's folder" asserts that every script folder installs.
- Added: tests for scripts in separate folders under a shared wrapper, a deeper script listed first, a script at the top beside folders, and a folder sharing a name prefix; one test per Fluffy, REFramework, root, preset and loose lua installer for a parent folder named like the marker; nested `.ZIP`/`.7Z`/`.Rar` pass-through and the still-repacked case; a game with no demo and a demo named like the game, each for the executable, the mod folders, setup and the Steam save id; the Xbox helper still winning for a game with no demo.
- Changed: the default-tools test loads a demo build to check the demo launch button, because the template scaffold now ships `EXEC_DEMO = ""` and the button has no executable to show. The comment on the demo transforms describes the new default. Suite is now 152 tests.
- Added: red proof. 16 of the new and flipped tests fail against the template as it was at the last commit and pass with the fix.
- Note: a lua mod that already has a `reframework` or `autorun` folder still goes to the Fluffy re-zip installer. That is intended, so the routing rows stay as plain routing tests.

## [2026-10-09]

- Added: the suite, 137 tests. Covers registration and the priority ladder (spec mod types, the explicit Fluffy mod and preset types, the five detected installers and the re-zip catch-all, no fallback); the nine toolbar actions; the toggles (`reZip`, `allowSymlinks`, `setupNotification`, `useRefNightly`, the Xbox logic and the demo executable), including a load with the other toggle values that also runs the contract checks; routing across every installer with case handling, the `reframework` and `autorun` folder rule for lua mods, FOMOD and game-id rejection for each installer with and without `reZip`; install output for every installer, with and without a wrapper folder; the re-zip installer against a real temporary staging folder (pass-through of nested archives, repack name, 7-Zip awaited); game definition (mod type targets, executable choice between base, Xbox helper and demo, launcher per store, store lookup); the tiered game version (executable, demo executable, `appxmanifest.xml`, the `0.0.0` fallbacks and their log lines); setup (mod folders for the base, demo and Xbox builds, Fluffy and REFramework downloads from Nexus and from the GitHub nightly, pinned file id versus the newest main file, login before download, sequencing, notices, dispatched actions, failure reporting and the page opened); the post-deploy reminder and the Run Fluffy button; the toolbar actions; and the Steam save folder lookup against a fake Steam folder and registry.
- Added: mutation check. 638 of 700 generated breaks of a scratch copy (operators, literals, strings, `await`s) turned the suite red. The 62 survivors are all dead or unobservable: unused scaffold code (`getAllFiles`, `purge`, `deploy`, the Fluffy pak, plugin and config constants, the unused `pathPattern` placeholders, `GOGAPP_ID`, `XBOX_PUB_ID`), values the suite overrides or that are overwritten before use (`STEAMAPP_ID_DEMO`, the initial module variables, the `GAME_VERSION` label), `void 0` written as `void 1`, ternaries whose `!` lands on a call result, a radix of 11 for digit strings, an error text that a catch swallows, and a redundant `await` in an async arrow.
- Added: `known gap` tests for four template defects, each of which turns red when the template is fixed: a nested archive with an upper-case extension is repacked inside another zip; a game with no demo (`EXEC_DEMO` set to `""`, the documented value) and the Xbox logic on launches an empty executable and points the mod folders at the demo's; a demo executable named like the game executable (the scaffold default, and used by three shipped games) makes every install look like the demo; and `runFluffy` lists `"EACCESS"` instead of `"EACCES"`, so an access-denied failure is never offered for reporting, on both failure routes.
- Note: `getSavePath` returns `userdata/<user id>/<app id>`. The `remote/win64_save` part is commented out in the template, and `resources/templates/TEMPLATE_REFRAMEWORK_FLUFFY.md` said `.../remote`; the doc is corrected.
- Note: a lua mod that already has a `reframework` or `autorun` folder is not taken by the loose lua installer, so it falls to the Fluffy re-zip installer. The suite pins that as the current routing.
