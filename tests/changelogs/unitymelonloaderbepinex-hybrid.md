# unitymelonloaderbepinex-hybrid suite Changelog

Covers `template-unitymelonloaderbepinex-hybrid`. Suite file: `tests/templates/unitymelonloaderbepinex-hybrid.test.js`.

## [2026-10-19]

- Changed: the Mono game with two executables test expects `UnityPlayer.dll` as the required file instead of the managed assembly. The template switched to the root file (see its changelog entry of this date) because the two builds name their data folders differently; the suite had not followed and was the one red test in `npm test`.

## [2026-10-11]

- Changed: the template fixes listed in its changelog entry of this date. The `known gap` tests for the swapped custom-loader names, the wrapper-name cuts (root, MelonLoader, BepInExConfigManager, custom mod data file, plugins folder), the deconflict and purge custom-loader checks, the MelonLoader button, the alt build version and `EACCESS` now assert the fixed result and lost their `known gap:` prefix. The test that pinned "a dismissed dialog lets the install go ahead" asserts the install is cancelled.
- Added: a loop over the four folder branches of the plugin sorter (plugins, patchers, Mods, Plugins) in a wrapper named like the folder; a custom mod data file named like its wrapper folder; every kind of refusal (BepInEx beside MelonLoader, the reverse, a mixed archive, a custom plugin beside BepInEx, a BepInEx plugin beside the custom loader) cancelled when the dialog answers Cancel or Close, and still going ahead with `preventPluginInstall` off; a second MelonLoader button test (a forced download when MelonLoader is already installed); the alt build keeping the manifest path only when the Xbox helper is present; the `.NET` notice shown exactly once; and a plugin and a patcher (or a Melon mod and plugin) in one archive sorted the same way whichever dll is read last, by delaying each file in turn. Suite is now 457 tests.
- Added: a table test over the installers that flatten to a marker file (BepInEx, MelonPreferencesManager, game assembly, assets, custom mod data file, custom loader file and installer, save), a loose plugin, and a custom loader mods folder: a parent folder named after the marker's whole file name must not stay in any destination. Found by reverting each fixed cut one at a time (9 of 12 hybrid sites were unguarded). Suite is now 467 tests.
- Added: red proof. 19 of the new and flipped tests fail against the template as it was at the last commit and pass with the fixes.

## [2026-10-10]

- Added: the suite, 450 tests. Both bundled downloader modules are faked for most tests (`downloader.js`, `bepinexbe_downloader.js`), and a slow variant of the fake shows whether a caller waits for a download. Covers registration and the priority ladder (the fourteen spec mod types, assembly and assets, the installers, the twelve toolbar actions, the three event handlers); the game definition (mod type folders, executable choice between base, Xbox helper and second executable, launcher per store); the toggles (`isXna`, Mono versus IL2CPP, `hasCustomMods`, `hasCustomLoader`, `customLoaderInstaller`, the save installer, no fallback, a loader served from the game's Nexus page), including loads with other toggle values that also run the contract checks; routing and FOMOD handling for every installer, with and without the optional ones; install output for every installer, with and without a wrapper folder, and the root installer against a real temporary staging folder for a build with its own data folder; the plugin sorter against real dll contents (BepInEx plugins and patchers, MelonLoader mods and plugins with the generated manifest, unknown dlls, the folder name a loose plugin is wrapped in, every refusal dialog and the cancellation it raises, the custom loader branches); the fallback and unknown-dll notices and their buttons; the loader choice dialog and each download it starts; the conflict dialog and each removal it starts; `setup` (folders created, optional notices, the .NET check, the preferences manager path reassigned); the version checks and every requirement set; the deploy and purge handlers; the tiered game version (version file, Xbox manifest, executable, Steam, Epic, GOG, hash with its cache); the save folder; the toolbar and download buttons; the three loaders served from a Nexus page; the custom loader's installer reminder and launch; and the bundled `bepinexbe_downloader.js` as the real module, offline, against a fake builds.bepinex.dev index page, including the template's own Bleeding Edge requirement.
- Added: mutation check. The first pass broke the template's `index.js` 1485 ways (operators, literals, strings, `await`s) and 1185 of the 1480 valid breaks turned the suite red. About 100 of the 295 survivors were real gaps and are now covered (FOMOD guards per installer, unwrapped installs, exact dialog wording and cancellation errors, downloads and removals that must be awaited, the custom loader branches, the base-executable version path). A second pass over the survivors killed 224 more. About 60 of the 78 that remain are dead or unobservable: unused constants and scaffold placeholders, the unused `getSavePath`, `void 0` written as `void 1`, `getDiscoveryPath`'s null checks (the value is always an object), error text a catch swallows, radix 11 for epoch digits, an unused indicator-file name. The ten that were real gaps were closed after that pass and have not had a third mutation pass.
- Added: `known gap` tests for template defects, each of which turns red when the template is fixed: the two custom loader mod types carry each other's display names; with a mod-based custom loader, conflict resolution never removes the custom loader and a purge tells the user to run an installer it does not have; the Download Latest MelonLoader button fetches the upstream release even for a fork served from the game's Nexus page; a build with its own executable reports game version `0.0.0`, because the alternative build is marked with the same string as the Xbox build; a destination cut at the first occurrence of the folder name keeps a wrapper whose name ends in that name, for the root, MelonLoader, config manager, custom data and plugins folder installers; and `"EACCESS"` instead of `"EACCES"` in the custom loader installer launch.
- Note: `resources/templates/TEMPLATE_UNITYMELONLOADERBEPINEX_HYBRID.md` is corrected. It listed a Remove MelonPreferencesManager button and an Open Config Folder button that the template does not have, and put the custom loader installer behind `customLoaderInstaller` instead of `hasCustomLoader`. It now also says which buttons need a placeholder filled in and what `isXna` drops (the Bleeding Edge button stays).
- Note: the placeholder Xbox id equals the placeholder Steam id, which switches the Xbox logic on by default; a suite that wants it off sets a different `XBOXAPP_ID`.
