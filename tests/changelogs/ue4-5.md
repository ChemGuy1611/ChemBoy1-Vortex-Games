# ue4-5 suite Changelog

Covers `template-ue4-5`. Suite file: `tests/templates/ue4-5.test.js`.

## [2026-10-27]

- Changed: the engine version test that wrote the executable's version now mocks a real engine version (`5.3.2.0`, expects `5` / `3`). It used to accept the harness default executable version (`1.2...`) as an engine version, which is the defect the template fixed this date.
- Added: two engine version tests. An executable reporting the game's own version (`1.0.0.0`) falls back to `ENGINE_VERSION`, and with `exeHasGameVersion` on the shipping executable is never read and `ENGINE_VERSION` is written.

## [2026-10-22]

- Changed: the `hasModKit` registration test expects the ModKit mod type's new display name, `ModKit Mod` (was `ModKit mod`), after the template rename of 2026-10-21.

## [2026-10-11]

- Changed: the template fixes listed in its changelog entry of this date. Nine of the ten `known gap` tests (the four wrapper-name cuts and the Xbox combo `ue4ssModFolder`, the three upper-case `.PAK` readers, the Open LogicMods Folder button) now assert the fixed result and lost their `known gap:` prefix. The tenth, `getBinariesFolder`, is not a defect: the helper feeds a tool with `relative: true`, so it is now an ordinary test of what it answers. The two `beatsPakInstaller` tests that followed `logicModsLoadOrder` now follow `ue4ssLoadOrder`, and a third test shows the LogicMods load order toggle alone no longer matters.
- Added: tests for the UE4SS mod folder on the Xbox build (one and several mods, a file named `Scripts` ignored), the same folder on a build with folder entries, the ModKit installer with no usable `modPluginName` (empty, wrong type, null) and with no wrapper, and `preSort` with a mod missing from state or without attributes. Suite is now 475 tests.
- Added: one test per installer that flattens to a marker (UE4SS proxy dll, signature bypass dll, ModKit, config, save, UE4SS scripts and dlls): a parent folder named after the marker's whole name must not stay in any destination. Found by reverting each fixed cut one at a time (7 of 10 ue4-5 sites were unguarded). Suite is now 482 tests.
- Added: red proof. 17 of the new and flipped tests fail against the template as it was at the last commit and pass with the fixes.
- Added: 72 tests found by a mutation check of the suite (each generated break of the template source, one at a time, must turn a test red), in two rounds. Round one, 60 tests: the FOMOD variants for every installer, upper-case marker files and bare-archive installs, the per-store Save compatibility list (sync and async), the drive check for every `preferHardlinks` and `IO_STORE` pair, a separate save location, the exact shape of the notices (More button, question dialog, suppress and report flags), an empty or one-character stored load order, the enabled-flag filter, `mods.txt` indentation and the Keybinds neighbour, the update guard, the FOMOD retag with an upper-case `.PAK` and a game-root layout, the Steam library folder lookup, placeholder store ids, the GOG version value name, the signature bypass download options and login, and a collection with an empty LogicMods list. Round two, 12 tests: the executable lookup without Xbox support when only one of the Epic, GOG or demo executables differs from the Steam one; the drive check with `IO_STORE` off and `preferHardlinks` at its default; a folder inside the save folder left alone while `hasUserIdFolder` is off; the Config type not offered before the game is discovered; a UE4SS folder without Vortex's marker file getting no mod id even when a mod names it (stored and fresh paths); the legacy pak sort counting exactly two files; `setGameVersionAsync` answering nothing when no known executable is there; the save installer refusal carrying `skipped: false` and an error-type notification; and `setup` waiting for the UE4SS (GitHub and Nexus) and signature bypass downloads to finish.
- Added: two more `known gap` tests, each of which turns red when the template is fixed: the UE4SS combo installer and the LogicMods load order reader record an upper-case `.PAK` with its extension, as the LogicMods installer already did.
- Changed: the fake downloader and the Nexus login fake take a `delay`, so a caller that does not wait for a download is told apart from one that does.
- Note: of 2665 generated breaks, the first run of the 395-test suite caught 1353, the suite after round one 1457, and after round two 1474. 1021 of the survivors sit in the React components, which are registered but not rendered, so they are not covered by design. Of the other 291 survivors of the first run, 104 were closed by round one and 17 more by round two. The remaining 170 are judged dead or equivalent: log, error and dialog text, placeholder constants, `void 0` remnants of compiled optional chaining, a dropped `await` on real file writes or on an async arrow that returns the same promise, the unread `hasServer` toggle, the unused `purge` and `didPurge` helpers, `radix 10`, and lower-casing constants that are already lower case.

routing and FOMOD handling for every installer; install output for every installer (pak with its multi-file dialog, UE4SS combo including the Xbox Win64 to WinGDK rename, LogicMods, UE4SS, scripts and dll against a real temporary staging folder with and without the `enabled.txt`, root, ModKit, signature bypass, config and save with the same-drive checks and their notices, the Binaries fallback and its notice);
